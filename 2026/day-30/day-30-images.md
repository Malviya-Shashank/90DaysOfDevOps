# Day 30 – Docker Images & Container Lifecycle

## Overview

Today I explored **Docker images and the container lifecycle**. Understanding how images work and how containers move through different states is essential for managing applications in a containerized environment.

Docker images act as **blueprints**, while containers are **running instances of those blueprints**.

Learning this relationship is critical before moving into advanced topics like **Dockerfiles, Compose, and Kubernetes**.

---

# Task 1 – Docker Images

## Pull Docker Images

Pulled commonly used images from Docker Hub.

```bash
docker pull nginx
docker pull ubuntu
docker pull alpine
```

These commands download the images from Docker Hub to the local system.

---

## List Docker Images

To view all downloaded images:

```bash
docker images
```

Example output:

```
REPOSITORY   TAG       IMAGE ID       SIZE
nginx        latest    abc123         180MB
ubuntu       latest    def456         77MB
alpine       latest    ghi789         7MB
```

---

## Compare Ubuntu vs Alpine

| Image | Size | Reason |
|------|------|------|
| Ubuntu | ~70MB | Full Linux distribution |
| Alpine | ~7MB | Minimal Linux distribution |

**Why Alpine is smaller:**

- Uses **musl libc** instead of glibc
- Minimal packages installed
- Designed specifically for containers

Because of its small size, **Alpine is widely used in Docker images for production applications.**

---

## Inspect an Image

To view detailed information about an image:

```bash
docker inspect nginx
```

This shows:

- Image ID
- Layers
- Environment variables
- Default commands
- Metadata

---

## Remove an Image

To delete an image:

```bash
docker rmi ubuntu
```

This removes the image if it is not being used by any container.

# Task 2 – Image Layers

Docker images are built using **layers**.

Check image layers using:

```bash
docker image history nginx
```

Example output:

```
IMAGE          CREATED         CREATED BY                SIZE
abc123         2 days ago      /bin/sh -c #(nop)         0B
def456         2 days ago      apt-get install nginx     120MB
ghi789         2 days ago      base layer                60MB
```

---

## What Are Image Layers?

Docker images are built using a **layered file system**.

Each instruction in a Dockerfile creates a **new layer**.

Example layers:

```
Base OS Layer
     ↓
Package Installation
     ↓
Application Code
     ↓
Configuration
```

---

## Why Docker Uses Layers

Layers provide several benefits:

### Faster Builds
If a layer hasn’t changed, Docker reuses the cached version.

### Storage Efficiency
Multiple images can share common layers.

### Faster Downloads
Docker only downloads layers that do not exist locally.

This layered architecture makes Docker **efficient and fast**.

# Task 3 – Container Lifecycle

A container goes through several states during its lifecycle.

### 1️⃣ Create a Container (without starting)

```bash
docker create nginx
```

This creates a container but does not run it.

---

### 2️⃣ Start the Container

```bash
docker start <container_id>
```

The container moves from **created → running**.

---

### 3️⃣ Pause the Container

```bash
docker pause <container_id>
```

This freezes all processes inside the container.

---

### 4️⃣ Unpause the Container

```bash
docker unpause <container_id>
```

The container resumes execution.

---

### 5️⃣ Stop the Container

```bash
docker stop <container_id>
```

Gracefully stops the container.

---

### 6️⃣ Restart the Container

```bash
docker restart <container_id>
```

Stops and starts the container again.

---

### 7️⃣ Kill the Container

```bash
docker kill <container_id>
```

Forcefully stops the container immediately.

---

### 8️⃣ Remove the Container

```bash
docker rm <container_id>
```

Deletes the container permanently.

---

## Check Container Status

After each step, run:

```bash
docker ps -a
```

This shows container states such as:

- created
- running
- paused
- exited

# Task 4 – Working with Running Containers

## Run Nginx Container in Detached Mode

```bash
docker run -d --name my-nginx -p 8080:80 nginx
```

Access in browser:

```
http://localhost:8080
```

---

## View Container Logs

```bash
docker logs my-nginx
```

Logs show output generated by the container.

---

## Real-Time Logs

```bash
docker logs -f my-nginx
```

`-f` follows logs in real time.

---

## Exec Into Container

```bash
docker exec -it my-nginx bash
```

This opens an interactive shell inside the container.

Example commands inside container:

```bash
ls
ps aux
```

---

## Run Command Inside Container

Instead of entering the shell:

```bash
docker exec my-nginx ls /
```

This executes a command directly inside the container.

---

## Inspect Container

```bash
docker inspect my-nginx
```

Important information available:

- Container IP address
- Port mappings
- Mounted volumes
- Network configuration

---

# Task 5 – Docker Cleanup

## Stop All Running Containers

```bash
docker stop $(docker ps -q)
```

Stops every running container.

---

## Remove All Stopped Containers

```bash
docker container prune
```

Deletes all stopped containers.

---

## Remove Unused Images

```bash
docker image prune
```

Removes dangling images.

---

## Check Docker Disk Usage

```bash
docker system df
```

Example output:

```
TYPE            TOTAL     ACTIVE    SIZE
Images          5         2         500MB
Containers      3         1         50MB
Volumes         2         1         200MB
```
