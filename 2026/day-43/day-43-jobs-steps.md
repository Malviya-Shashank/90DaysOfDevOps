# Task 1 – Multi-Job Workflow

I created a workflow with **three dependent jobs**.

Workflow file:

```
.github/workflows/multi-job.yml
```

### multi-job.yml

```yaml
name: Multi Job Workflow

on:
  push:

jobs:

  build:
    runs-on: ubuntu-latest
    steps:
      - run: echo "Building the app"

  test:
    runs-on: ubuntu-latest
    needs: build
    steps:
      - run: echo "Running tests"

  deploy:
    runs-on: ubuntu-latest
    needs: test
    steps:
      - run: echo "Deploying"
```

### Result

- `build` runs first
- `test` runs only after `build` succeeds
- `deploy` runs only after `test` succeeds

The workflow graph showed a **clear dependency chain**.

# Task 2 – Environment Variables

I used environment variables at **workflow, job, and step levels**.

Workflow file:

```
.github/workflows/env-vars.yml
```

### env-vars.yml

```yaml
name: Env Variables Demo

on:
  push:

env:
  APP_NAME: myapp

jobs:
  env-job:
    runs-on: ubuntu-latest

    env:
      ENVIRONMENT: staging

    steps:
      - name: Print variables
        env:
          VERSION: 1.0.0
        run: |
          echo "App: $APP_NAME"
          echo "Environment: $ENVIRONMENT"
          echo "Version: $VERSION"

      - name: GitHub context variables
        run: |
          echo "Commit SHA: ${{ github.sha }}"
          echo "Triggered by: ${{ github.actor }}"
```

### Result

All variables were successfully accessed:

- Workflow level → `$APP_NAME`
- Job level → `$ENVIRONMENT`
- Step level → `$VERSION`

# Task 3 – Job Outputs

I passed data from one job to another using **outputs**.

Workflow file:

```
.github/workflows/job-output.yml
```

### job-output.yml

```yaml
name: Job Outputs Demo

on:
  push:

jobs:

  generate-date:
    runs-on: ubuntu-latest
    outputs:
      today: ${{ steps.set-date.outputs.date }}

    steps:
      - name: Set date
        id: set-date
        run: echo "date=$(date)" >> $GITHUB_OUTPUT

  use-date:
    runs-on: ubuntu-latest
    needs: generate-date

    steps:
      - name: Print date
        run: echo "Today's date is ${{ needs.generate-date.outputs.today }}"
```

### Result

The second job successfully printed the date generated by the first job.

### Why use outputs?

- Share data between jobs
- Pass build artifacts metadata
- Control pipeline flow dynamically

# Task 4 – Conditionals

I tested different conditional executions.

Workflow file:

```
.github/workflows/conditionals.yml
```

### conditionals.yml

```yaml
name: Conditionals Demo

on:
  push:
  pull_request:

jobs:
  conditional-job:
    runs-on: ubuntu-latest

    steps:
      - name: Run only on main branch
        if: github.ref == 'refs/heads/main'
        run: echo "This runs only on main branch"

      - name: Intentional failure
        run: exit 1

      - name: Run on failure
        if: failure()
        run: echo "Previous step failed"

      - name: Continue on error example
        continue-on-error: true
        run: exit 1

  push-only-job:
    if: github.event_name == 'push'
    runs-on: ubuntu-latest

    steps:
      - run: echo "This job runs only on push"
```

### Observations

- `if:` controls execution based on conditions
- `failure()` runs only if previous step fails
- `continue-on-error: true` allows workflow to continue even if a step fails

# Task 5 – Smart Pipeline

I created a pipeline combining multiple concepts.

Workflow file:

```
.github/workflows/smart-pipeline.yml
```

### smart-pipeline.yml

```yaml
name: Smart Pipeline

on:
  push:

jobs:

  lint:
    runs-on: ubuntu-latest
    steps:
      - run: echo "Running lint checks"

  test:
    runs-on: ubuntu-latest
    steps:
      - run: echo "Running tests"

  summary:
    runs-on: ubuntu-latest
    needs: [lint, test]

    steps:
      - name: Branch type
        run: |
          if [[ "${{ github.ref }}" == "refs/heads/main" ]]; then
            echo "Main branch push"
          else
            echo "Feature branch push"
          fi

      - name: Print commit message
        run: echo "${{ github.event.commits[0].message }}"
```

### Result

- `lint` and `test` ran in parallel
- `summary` ran only after both completed
- It printed:
  - Branch type (main or feature)
  - Commit message

# Key Learnings

1. `needs:` defines **job dependencies** and execution order.
2. Environment variables can be defined at **workflow, job, and step levels**.
3. Outputs allow passing data between jobs.
4. Conditionals (`if:`) control when jobs or steps run.
5. `continue-on-error` helps prevent pipeline failure for non-critical steps.
